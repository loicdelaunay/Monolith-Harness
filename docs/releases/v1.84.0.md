# Monolith Harness 1.84.0

GUI and CLI share version 1.84.0. Android is distributed as a separate signed preview.

## Changes

- White monolith identity with a cyan accent for desktop, orange for the CLI icon and terminal mark, and green for Android launcher/startup imagery. Each host owns its source so icon exports preserve its variant.
- Shared platform-neutral Core with separate Core.Desktop and Core.Mobile. Desktop tools, storage adapters and native dependencies remain in the desktop engine.
- Android: Material 3 presentation, project/chat sidebar, settings and skills, private documents/scoped memory/public HTTPS web tools, global Refuse all / Ask all / Allow all policy, native Markdown, grouped tool summaries and a compact composer with header model selection.

[Changelog](https://github.com/loicdelaunay/Monolith-Harness/blob/v1.84.0/CHANGELOG.md) · [Android guide](https://github.com/loicdelaunay/Monolith-Harness/blob/v1.84.0/docs/android-portable.md)

## Downloads and updates

Choose GUI or CLI for Windows x64 or Fedora Linux x64. Archives contain only the executable, license and startup instructions; no database, API keys, logs or workspace. Historical Windows-name aliases contain identical downloads. SHA256SUMS.txt lists all fingerprints.

Close desktop applications and replace only their executable. Keep database.sqlite, workspace/ and existing resources. Android APK installation and its independent data/signing boundaries are documented in the [Android preview release](https://github.com/loicdelaunay/Monolith-Harness/releases/tag/android-v1.84.0).

## Validation scope

Windows GUI and CLI were compiled and published locally with matching versions. GitHub Actions rebuilds Windows/Fedora, validates the allowlisted archive contents and remote digests, and prepares both releases as drafts before making them public. Android packaging uses its durable release certificate. The color change did not request a new automated functional suite; previous device checks are described with their scope in the Android guide. macOS packaging/runtime and all Android provider/tool combinations are not validated by this release.


The existing automatic **Desktop compatibility** workflow still fails the CLI assertion `CLI terminal tools start in the current conversation workspace` on Windows and Fedora. The same assertion failed in version 1.77.1: [previous run](https://github.com/loicdelaunay/Monolith-Harness/actions/runs/37916064285), [current run](https://github.com/loicdelaunay/Monolith-Harness/actions/runs/38077853960). The [release packaging workflow](https://github.com/loicdelaunay/Monolith-Harness/actions/runs/38077853936) succeeded; this does not imply a fully passing functional suite.
