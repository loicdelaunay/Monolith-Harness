# Monolith Harness GUI 1.33.1

## Nouveautés depuis 1.29.2

- Création et gestion de projet partagent les mêmes réglages : nom, icône, couleur avec aperçu, plusieurs dossiers par défaut et import facultatif des règles. La première conversation hérite immédiatement des dossiers choisis.
- **Outils → Consommation** : graphiques et détail des tokens, filtres Aujourd’hui / 3 / 7 / 30 jours / 1 an, fournisseur, modèle, projet et activité ; export du détail par copie CSV. Les compteurs réels et estimés sont distingués.
- **Outils → AI Generated detector** : intégration des vrais moteurs SlopTotal pour texte, URL et documents, résultats en direct, scores par paragraphe et traces des constructeurs de sites IA. Configurer un serveur SlopTotal local ou distant ; l’installation locale facultative nécessite Docker et télécharge plusieurs Go de modèles à son premier lancement. Les scores ne prouvent pas l’auteur d’un texte.
- Guide de bienvenue illustré pour les nouveaux profils : thème, fournisseur et skills. Sélecteur modèle/réflexion plus lisible dans les petites fenêtres et graphique d’utilisation du contexte.
- Nom et logo dans Apparence, noms personnalisés sur deux lignes, libellés Git / File Index avec badge Beta et détails des skills.
- Menu contextuel sur les fichiers et dossiers locaux mentionnés dans les réponses : ouvrir, ouvrir dans le navigateur ou ouvrir le dossier du fichier.

## Plateformes et installation

GUI et CLI à la même version : Windows x64, macOS Apple Silicon, macOS Intel et Linux x64 (construction Fedora 44). Chaque archive contient uniquement `MonolithHarness.exe` ou `MonolithHarness`, la licence et les instructions. Vérifier les téléchargements avec **SHA256SUMS.txt**.

Fermer l’application, sauvegarder son dossier puis remplacer uniquement l’exécutable. Conserver `database.sqlite`, les ressources et les paramètres. Les installations antérieures à 1.29.2 doivent remplacer manuellement leur ancien lanceur. Installer GUI et CLI dans des dossiers séparés.

Sur macOS/Linux, extraire les archives avec `tar -xzf` pour conserver les permissions. Les builds macOS ne sont ni signés ni notariés ; les interactions natives nécessitent une validation manuelle sur un Mac. La GUI Linux utilise X11/XWayland, GTK3 et WebKitGTK pour son navigateur.
