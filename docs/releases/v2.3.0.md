# Monolith Harness 2.3.0

## Desktop idle consumption

- Token-speed indicators stop refreshing without a generation and restart from activity notifications, including in-process subagents.
- Model and command-validation indicators refresh only while visible work needs them. Unchanged text, tooltips and indicator properties are retained.
- Terminal output uses change notifications with grouped visual updates instead of continuous polling. Background commands continue running and their retained output is refreshed when shown.
- Scheduled tasks wake at their next deadline and on task edits. Without an active deadline, the scheduler sleeps; file-notification failures retain a fallback. Existing per-profile ownership and non-overlapping task execution are preserved.
- Update checks, automatic-install retries and optional conversation maintenance share a timer queue. Disabled maintenance does not wake it.
- Background animations, spinners and periodic presentation updates pause when the main window is inactive or minimized, then resume when needed.

Hidden browser pages use native WebView2 suspension when supported by the Windows backend. Tabs in a conversation with an active agent, and pages still navigating, remain available. Backends without native suspension hide their views but may continue running page scripts. Model generations, commands and due tasks are not cancelled by visual suspension.

## Idle diagnostics

**Tools → Debug → Measure idle (30 s)** pauses diagnostic sampling, activates the main window and records process CPU together with refresh, layout and frame counters. Leave the application untouched during the sample.

The optional Uno frame observer counts drawn frames without subscribing to the public animation-frame event. Unsupported renderers explicitly report the counter as unavailable. Layout updates are distinct from rendered frames. CPU excludes external browser, terminal, model and server processes; GPU usage is not measured by this tool. No hardware-specific idle percentage or interactive performance benchmark is claimed for this release.

See [idle behavior and measurement details](https://github.com/loicdelaunay/Monolith-Harness/blob/v2.3.0/docs/optimisations-repos-2.3.0.md).

## Title bar polish

The desktop header has two fewer pixels of bottom padding and a subtle theme-aware hover effect on the bar and chat-tool buttons, including selected buttons. This change does not claim to fix the intermittent missing-header startup issue.

## Downloads and updating

- GUI, CLI and Server: portable Windows x64 and Linux x64 downloads.
- Flutter Android: signed ARM64 APK aligned to 2.3.0+156, retaining the existing durable signing identity. The optimizations above concern the desktop edition; version alignment does not add these native desktop features to Android.
- SHA-256 manifests accompany each release. Windows GUI and CLI include compatibility aliases for older update clients.

Portable archives contain only the executable, license and startup instructions. Keep your existing database, workspace and server configuration when updating. No user data, API credentials, logs or private configuration are included.

The local Windows GUI, CLI and Server publications compiled without warnings. Public packages are built and validated by the release workflow.

## Existing validation limitation

The compatibility suite's database-upgrade check (`Mise à niveau d’une base existante sans perte d’état`) failed on Fedora during release preparation, as it already did on Windows and Fedora for [2.2.1](https://github.com/loicdelaunay/Monolith-Harness/actions/runs/39470632032). This release does not change database schema or migration code. Full compatibility-suite success has not been established.
