# Monolith Harness 1.47.0

## Local model browser

**Settings → Providers → Local** now includes **Browse…** beside the model directory. The native folder picker keeps the current path when cancelled, and the chosen directory is saved with the provider settings.

**Hugging Face** opens in an independent, resizable window. Search and Chat/Image filters sit above two panes: a model list on the left and repository details on the right. Details include downloads, likes, modification date, licence, available files/quantizations, a machine compatibility estimate and the model card. Compatible files appear first; unsupported components remain visible with their reasons. The panes stack when the window is smaller, and actions stay at the bottom right.

Cancelling a download removes its partial file and keeps the browser available. Closing the browser or its provider settings stops pending work. Downloads retain pinned repository revisions, file-size checks, SHA-256 verification when provided, and model-header inspection before import. Automatic GUI updates also wait for the independent browser to close.

Supported formats remain standalone GGUF for chat and full SD 1.x, SD 2.x and SDXL Safetensors checkpoints for images. Protected repositories require a read token and licence acceptance on Hugging Face.

## Downloads and updating

Both **GUI and CLI 1.47.0** have **Windows x64** and **Linux x64** archives. The CLI retains its existing local-model workflow; its version and shared engine are aligned with the GUI. macOS publication remains paused.

Each archive contains only its standalone launcher, **LICENSE** and **README.txt**. No databases, keys, logs, profiles or downloaded models are included. Windows legacy-name archives are identical compatibility aliases; each release includes **SHA256SUMS.txt**.

Extract GUI and CLI into separate writable folders. To update manually, close the application and replace only **MonolithHarness.exe** on Windows or **MonolithHarness** on Linux. Keep **database.sqlite** and existing resources.

## Validation

- 16 offline catalogue checks cover metadata, pinned model cards, read-token forwarding, bounded card size, download integrity, existing-file protection and cancellation.
- 21 native GUI scenarios under Linux/Xvfb cover directory selection/cancellation with a simulated picker, independent-window lifecycle, model and file selection, responsive layout, theme changes, empty/error states, download cancellation/cleanup and verified import with small fixture files.
- A live public Hugging Face repository metadata request and its pinned model-card URL returned successfully.

The Windows folder chooser has not been exercised on Windows hardware in this environment. These checks do not validate inference throughput or loading full model weights.
