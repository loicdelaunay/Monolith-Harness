# Monolith Harness 2.2.1

## Advanced desktop rendering settings

A new **Settings → Advanced** page, immediately before Reset, groups the interface rendering controls:

- Automatic, OpenGL or Vulkan rendering on Uno Desktop for Windows and Linux.
- Hardware acceleration on/off; disabling it selects CPU software rendering.
- The existing Windows graphics card power preference, moved from General while retaining the saved selection.
- Auto refresh pacing, display synchronization, or a manual target from 15 to 500 frames/s.

Rendering changes take effect after restarting the application. Vulkan falls back to OpenGL and then software rendering when necessary. On macOS the GPU renderer is Metal. Skia-specific controls are unavailable in the optional native WinUI edition.

On Windows, the graphics card section shows adapters whose 3D activity has been observed for this application process when the system counters can identify them. It can list several adapters; this observation does not identify a specific rendering surface. Software rendering is shown as CPU, and unavailable names are reported explicitly.

The refresh section shows the main window display's current nominal refresh in Hz, updated while the page is visible, separately from the rendering target applied at startup. The target is not a measurement of actual frames drawn. These settings affect the desktop interface, independently of AI model computation and embedded browser graphics settings.

## Action suggestions remain in the chat

Assistant responses accompanying action suggestions now remain in the main chat, including messages that also contain technical tool calls. The same rule applies during generation, after reopening a conversation and when virtualized messages are reconstructed. Technical tool details retain their activity grouping.

Action buttons continue to require a user click before work starts, with the existing tool permissions.

## Scroll investigation

The [rendering and scrolling report](https://github.com/loicdelaunay/Monolith-Harness/blob/main/docs/rapport-rendu-scroll-reflexion-2026-10-20.md) describes the current virtualization, message layout costs and frame pacing. It distinguishes code observations from causes that need profiling on a real conversation. This release adds rendering controls and the requested grouping correction; it does not claim a measured scrolling performance improvement.

## Downloads and updating

- GUI, CLI and Server: portable Windows x64 and Linux x64 downloads.
- Flutter Android: signed ARM64 APK aligned to 2.2.1+155 using the existing durable signing identity. The changes above concern the desktop edition; this version alignment does not add these desktop controls to Android.
- SHA-256 manifests accompany each release. Windows GUI and CLI include compatibility aliases for older update clients.

Portable archives contain only the executable, license and startup instructions. Keep your existing database, workspace and server configuration when updating. Downloads contain no user data, API credentials or private configuration.

The desktop compiles without warnings, and the local GUI, CLI and Server publications are aligned to 2.2.1. No new interactive performance benchmark is claimed.
