# Monolith Harness 2.1.1

## Guided questions in desktop chat

Question cards now combine responsive choice tiles with an accordion showing the answers to earlier questions. Choices can include Fluent icons and follow the active application theme. Pure free-text questions show a text field directly. Single selection remains the default; multiple selection must be explicitly requested by the model.

Radio buttons and checkboxes are centered with the icon and text, including multiline descriptions and 150% text zoom. Duplicate numbering is removed from question headers. Validation errors clear when an answer becomes valid. The card adapts to the available chat height, keeps its own scroll area and brings the active question into view. Footer buttons use an extra row when space or text zoom requires it.

## Optional action suggestions skill

In desktop Agent mode with a direct model provider, the new **Action suggestions** skill lets the AI offer buttons to:

- Continue work in the current conversation.
- Launch an agent in a dedicated discussion.
- Start a new discussion with a self-contained prompt.
- Add work to the current conversation queue.

Suggestions do not execute work until the user clicks. Prompts can be reviewed before selection. The chosen alternative is persisted and cannot be replayed by double-clicking or reopening the conversation. New discussions retain the project resources, sandbox and work mode; normal tool permissions still apply. Disable the system in **Settings → Skills**.

See the [action suggestions guide](https://github.com/loicdelaunay/Monolith-Harness/blob/main/docs/action-suggestions.md).

## Validation

The targeted native Uno application scenario passed 145 checks with an isolated database, dark and light themes, window widths from 420 to 1600 pixels and 150% text zoom. It covers single and multiple choice, custom answers, free text, validation, navigation, collapse/expand, cancellation, answer submission and layout measurements. It uses native control automation peers and rendered screenshots without remote model calls.

See the [report and captures](https://github.com/loicdelaunay/Monolith-Harness/blob/main/docs/qa/questions-2.1.1-20261019/report.md).

## Downloads and updating

- GUI, CLI and Server: Windows x64 and Linux x64 portable archives.
- Flutter Android: signed ARM64 APK, aligned to version 2.1.1 with the existing durable signing identity. The desktop features described above do not imply Android feature parity.
- SHA-256 checksums accompany each release. Windows GUI and CLI retain compatibility archive aliases for older update clients.

Portable archives contain only the executable, license and startup instructions. Keep your existing database and workspace when replacing the executable. No user data, API keys or private configuration is included.
