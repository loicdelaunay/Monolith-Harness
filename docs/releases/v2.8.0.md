# Monolith Harness 2.8.0

This release includes the changes prepared for 2.6.0, 2.7.0 and 2.8.0.

## Memory

- Two new options in Settings > Memory, in the GUI and the CLI, both disabled by default:
  - **Force read at conversation start**: before a conversation's first response, the application gives the model the 20 most recent accessible memories and asks it to check those relevant to the request.
  - **Force write at conversation end**: after each completed response, an extra memory-only request asks the model to save the exchange's durable facts. The chat history is not modified.
- Forced writes follow the usual permissions and project rules, are skipped in Plan mode, in Chat mode and with OpenCode / ACP agents, and their result appears in the end-of-response status. Their token usage is listed under the Memory activity of the dashboard.

## Reasoning

- Reasoning choices are limited to the levels declared by the model or its provider catalogue; only Auto is offered when capabilities are unknown. Minimal, Extra high and Maximum are available when supported. Chat, proofreader, shortcuts, scheduled tasks and the CLI share these capabilities.
- Responses show the requested level, the level sent, the transport parameters and any fallback. No reasoning uses an explicit disable in Chat, Agent and the proofreader; an incompatibility is reported instead of silently re-enabling reasoning.
- Benchmark: compare reasoning levels on the same reproducible tasks, with level selection, repetitions, alternating order, average latency, first item received, tokens and success on verifiable answers. The JSON report keeps answers and traces, including errors and partial results; the score only describes the evaluated tasks.

## Provider settings

- Redesigned Providers page: a searchable connection list on the left and details on the right, with Connection, Models and Advanced tabs separating authentication, chat models and technical settings. The list and details scroll independently; small windows get a back-to-list action.
- Connections show local logos, Duplicate/Delete actions in their context menu, an explicit replacement for the stored key and the connection result under the test. Model search keeps suggestions, multi-selection and pagination. Unsaved connection changes are flagged next to the save bar.

## CLI

- Accented French text in the Settings, queue, subagents, Git, terminals, memory and sandbox menus is displayed correctly.

## Downloads

GUI, CLI and Server are available for Windows x64 and Linux x64. Flutter Android is a signed ARM64 APK. SHA256SUMS.txt is included in every release.

## Validation and limits

- The full regression suite passed (800 checks), including the existing-database upgrade check reported as a known issue in 2.5.0: its expectation now includes the action suggestions enabled by the 2.1.1 migration.
- The full desktop UI smoke test passed in an isolated instance, including the Memory settings and the redesigned provider list and Models page.
- Windows GUI, CLI and Server publication completed locally.
- Forced memory steps are not available on Android, with OpenCode / ACP agents or in Chat mode. Force write adds one model request after each completed response.
