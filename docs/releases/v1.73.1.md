# Monolith Harness 1.73.1

GUI and CLI share version 1.73.1. This release includes the changes since 1.68.0.

## Highlights

- Slash skills work inside a sentence, such as `Update the branches /git`. Clicking a suggestion or pressing Tab/Enter completes the draft without sending it. The skill instruction is added when the full message is submitted. Chat mode also lists skills with availability indications.
- The compact quick-model popup now has a Material-inspired discrete slider, with thick rounded tracks, a vertical handle, level indicators and keyboard support. The three-dot icon switches between simple and advanced model selection.
- The permission menu can restrict each conversation and its subagents to attached files/folders. Outside access stays enabled by default for compatibility. When disabled, local executors and tools that cannot enforce the boundary are blocked; isolated commands remain available through the existing Docker/Podman sandbox. Saved approval grants and Allow all cannot override the boundary.
- Attachment previews use an inline collapse arrow and preserve per-conversation folding.
- The proofreader and translator use native editors instead of WebView. Interactive tool previews require explicit opt-in. Application theme colors drive Mermaid rendering.
- Adds project/chat drag-and-drop ordering, an empty-chat start action, model diagnostics in Settings, file-change proposals requiring review, richer CLI permission details and improved terminal scrolling.
- Fixes `Unknown portable resource folder` while opening conversations or preparing proposals, and adds isolated storage regression coverage.

See [CHANGELOG.md](https://github.com/loicdelaunay/Monolith-Harness/blob/v1.73.1/CHANGELOG.md) for details.

## Downloads

Choose the GUI or CLI archive for Windows x64 or Fedora Linux x64. Historical Windows archive-name aliases contain the same executable. `SHA256SUMS.txt` lists the fingerprints of all downloads.

Archives contain only the executable, license and startup instructions. They contain no database, credentials, logs or user workspace.

## Updating

Close the application, back up your workspace, and replace only the executable. Keep `database.sqlite`, `workspace/` and your existing resources. Startup migrates managed storage when needed. Optional Git, Docker/Podman, OpenCode and MCP integrations keep their own prerequisites.

## Validation

The GUI and CLI compile and are published locally on Windows x64 at 1.73.1. GitHub rebuilds and checks the download contents and fingerprints for Windows x64 and Linux x64 before making both releases public. The earlier proposal-storage regression run passed 107 checks across portable storage, conversation files and appearance/MCP settings; no additional local test suite was run for the latest UI changes.
